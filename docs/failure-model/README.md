# Failure model

| Event                                     | Durable behavior                                                                                    | Verification / limit                                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Worker killed during a handler            | Lease recovery/backoff grants a larger attempt fence; external effects may repeat                   | Public real-process crash check; measured recovery15.66s/three attempts                       |
| Schedulers killed/restarted or competing  | Durable requests wait or another scheduler dispatches; queue/worker locks preserve capacity         | Two-scheduler/two-worker public test, scheduler restart, queue active limit2                  |
| Duplicate submission                      | Same project/key/request returns original; changed request409; empty supplied key400                | Public API regression                                                                         |
| PostgreSQL unavailable                    | No acknowledged new request or durable completion without SQL confirmation; clients reconnect       | Earlier restart checks plus current real TCP blackhole/client-deadline regression             |
| Redis unavailable/OOM                     | New API admission503; cache bypass; acknowledged C++ jobs continue                                  | Replica quota, stale cache, transport/reconnect and memory tests; complete-stack stop/restart |
| Kafka unavailable                         | Committed events remain in PostgreSQL outbox while jobs execute                                     | Real broker stop, job completion, pending outbox and restart catch-up                         |
| Publisher stopped or acknowledgement lost | Pending/expired claims retry; duplicates are possible                                               | Real publisher stop/restart and broker-ack fault injection                                    |
| Consumer stopped or redelivery            | SQL inbox prevents duplicate effects; version prevents old state regression                         | Stop/restart, duplicate and unique out-of-order records, zero lag and namespace replay        |
| Invalid lifecycle schema/version          | Durable failure marker precedes offset advance; original retained Kafka record remains replayable   | Unknown schema and bigint-overflow poison records followed by valid records                   |
| Worker heartbeat expires                  | Worker is no longer eligible; existing leases have separate fences                                  | Crash checks exercise the stale availability window                                           |
| Long handler/cancellation/timeout         | Cooperative handlers renew/check ownership and fixed deadline; current cancellation resolves safely | Real sleep timeout/cancellation plus SQL ownership races                                      |
| Stale completion                          | Old worker/attempt/expired lease cannot overwrite current state                                     | SQL regression and crash recovery                                                             |
| Concurrent workflow predecessors          | Join waits for all successful parents; failure cancels descendants                                  | Real diamond timestamps and failure/retry/cancellation checks                                 |
| API graceful shutdown                     | Active SSE responses end before HTTP/SQL teardown                                                   | Ten-stream concurrent quota and abort regression                                              |
| Machine/volume loss                       | Requires backups/replication; process restart alone cannot recover destroyed durable storage        | No HA/automatic restore claim                                                                 |

Execution and event delivery are at least once. Durable result fencing is not external-effect idempotency. Six-second leases are not a bound on total recovery because heartbeat eligibility, retries, queue occupancy and load also matter. See FINAL_ENGINEERING_REPORT.md for measurements, sanitizer caveats and remaining risks.
